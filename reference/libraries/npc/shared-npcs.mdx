description: "Retain preparation ownership, publish hidden parts, drive clip time and await complete shutdown."

Your host owns the NPC's Minestom instance and the start token returned by
`NpcRenderer.prepare(request)`. Retain that token before observing asynchronous readiness.
A hidden ready handle and a visible published NPC are separate states.

## Prepare, publish and remove

<Steps>
<Step title="Construct a validated definition and request">
`NpcModel` contains immutable bones, parts, clips and sound cues. Bone parents precede their
children. In the example, the head is a child of the body and its local origin is its rotation pivot.
`NpcPart.model` names an item-model resource supplied by the demo pack.

Build `NpcSpawnRequest` with `builder(instance, model, transform).build()`. Optional named builder
settings choose render policy, mesh resolution, sound delivery and the host publication guard.
`toBuilder()` creates a new builder without modifying an existing request.
</Step>
<Step title="Retain preparation ownership">
`NpcRenderer.prepare(request)` returns an `NpcStart` immediately. `start.ready()` produces
`NpcPrepareResult.Ready` or `Rejected`. A ready handle still owns hidden parts; a rejected result
contains immutable, nonempty diagnostics.

Retain `start` even when readiness fails or is cancelled. Await `start.cancel()` in every failed
installation path so partial attachments and accepted work drain before your host reports completion.
</Step>
<Step title="Publish through the host guard">
Observe the stage returned by `handle.publish()`. Your production generation guard must check
that the installation is still valid and execute the publication operation synchronously and
atomically. The default demo guard immediately executes the operation.

A completed command stage describes server-side work; it does not acknowledge a client frame.
Argument failures and operational failures arrive through command stages. Operational failures
use `NpcOperationException` and retain their original cause.
</Step>
<Step title="Drain before stopping the host">
Invalidate your host generation and cancel the repeating tasks you installed. Await
`start.cancel()` or `handle.closeAsync()` before stopping the instance/server. Parent cleanup also
owns private copies, accepted movement I/O and in-flight sound callbacks.

`handle.closed()` observes final cleanup without initiating it. Closing is idempotent and does
not need another instance tick. Keep observing cleanup failures.
</Step>
</Steps>

`DemoApplication` shows this entire lifecycle with failure cleanup and a shutdown owner. Its
five-second blocking helper is for bootstrap/shutdown threads. In an instance callback, compose
stages into your lifecycle instead of blocking the scheduler that must execute the queued work.

## Drive absolute clip time

Shared `playClip("wave")` starts at zero; `playClip("wave", elapsedMillis)` chooses another
clip-local starting time. Neither installs a shared animation clock. The host calls
`advanceClipTo(elapsedMillis)` with an absolute time, including backwards seeks.

| API value | Unit |
| --- | --- |
| Clip duration, keyframes and `NpcPoseSampler.sample` time | Seconds |
| Shared `playClip` and `advanceClipTo` | Absolute clip-local milliseconds |
| Bone rotation and additive head yaw/pitch | Degrees |

This complete helper from the runnable example owns its tick driver and the resulting cleanup:

```java SharedNpcPlayback.java
package example;

import gg.grounds.npc.minestom.NpcHandle;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CompletionStage;

/**
 * Owns the shared clip clock and its repeating scheduler task.
 *
 * <p>{@code advanceClipTo} takes absolute clip-local milliseconds. At a nominal 20 ticks per second
 * this demo advances by 50 ms per tick, producing 50, 100, 150... rather than passing a repeated
 * delta of 50. It deliberately uses tick time, so animation slows with a lagging server. Numeric
 * model keyframes use seconds; personal presentations use their own monotonic clock inside the
 * library.
 */
final class SharedNpcPlayback {
  private final NpcHandle npc;
  private final CompletableFuture<Void> removed = new CompletableFuture<>();
  private long elapsed;
  private boolean closed;
  private Runnable cancelTicks = () -> {};

  SharedNpcPlayback(NpcHandle npc) {
    this.npc = npc;
  }

  synchronized CompletionStage<Void> tick() {
    if (closed) return CompletableFuture.completedFuture(null);
    return npc.advanceClipTo(elapsed += 50);
  }

  synchronized CompletionStage<Void> start(String clip) {
    if (closed)
      return CompletableFuture.failedFuture(new IllegalStateException("Demo NPC removed"));
    // A new clip starts at zero regardless of how long the server has already been running.
    elapsed = 0;
    return npc.playClip(clip, 0);
  }

  void onRemoval(Runnable cancelTicks) {
    boolean stop;
    synchronized (this) {
      stop = closed;
      if (!stop) this.cancelTicks = cancelTicks;
    }
    if (stop) cancelTicks.run();
  }

  CompletionStage<Void> remove() {
    Runnable stop;
    synchronized (this) {
      if (closed) return removed.minimalCompletionStage();
      closed = true;
      stop = cancelTicks;
      cancelTicks = () -> {};
    }
    try {
      // Cancel the host driver first; observe the asynchronous renderer drain before reporting
      // done.
      stop.run();
      npc.closeAsync()
          .whenComplete(
              (unused, error) -> {
                if (error == null) removed.complete(null);
                else removed.completeExceptionally(error);
              });
    } catch (Throwable error) {
      removed.completeExceptionally(error);
    }
    return removed.minimalCompletionStage();
  }
}
```

The demo adds 50 ms per nominal server tick, so animation slows when the server does. Resetting
the local elapsed counter starts a new clip at zero even after a long server uptime. Personal
presentations use a separate monotonic clock inside the library.

`stopClip()` stops the requested shared clip and renders the bind pose. `stopClipIfPlaying(id)`
only stops a matching request. `applyHeadLook(yaw, pitch)` changes the head subtree;
`applyTransform(transform)` waits for root relocation and still-owned private copies.

## Apply per-connection visual state

`applyViewerState(player, state)` applies scale/glow to one concrete online connection in the
owning instance. Scale must be finite and in `(0, 16]`. `clearViewerState(player)` removes that
connection's override. A reconnect with the same UUID receives new ownership.

Keep live handles, `Player` references, entity IDs and viewer overrides on their owning backend.
On a backend/proxy transfer, resolve the player and NPC at the destination and prepare new local
ownership. The renderer does not discover remote players or deliver network messages for your host.

## Decode authored numeric data

`NpcModelJson.decode(bytes, limits)` returns a complete `Success` or immutable `Failure.problems`.
Diagnostics include a stable code and an unambiguous field/JSON path; malformed UTF-8 and byte
overflow have distinct codes. Manual constructors apply the same model invariants synchronously.

Schema 1 permits at most 256 bones, 1024 parts, 128 clips, 4096 keys per channel and 300 seconds
per clip. `NpcDecodeLimits` can reduce these budgets. Models retain namespaced resource IDs and
typed `NpcLoopMode`, `NpcInterpolation` and `NpcBoneTrack` definitions while JSON wire names stay
unchanged. Sound metadata alone is silent; supply the appropriate host sound sink for delivery.
